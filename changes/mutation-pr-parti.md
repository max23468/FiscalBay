# Parti della mutation della PR riusate fra run

## Decisioni

| ID | Ambito | Sintesi della scelta / motivazione | Provenienza | Stato / requisito completo |
|---|---|---|---|---|
| D321 | **Parti della mutation della PR riusate fra run** | Il passo che prepara la matrice della mutation di una PR salva il piano, con parti, intervalli e impronta del sorgente di ogni modulo, nell'artefatto `mutation-plan-<run>`. Una parte riuscita in una run precedente della stessa PR vale anche se le altre parti sono di run diverse o se quella run è stata annullata, purché il commit sia antenato di quello provato ora, i cambi da allora non invalidino il modulo e il piano abbia la stessa impronta del sorgente attuale e gli stessi intervalli del riferimento, il piano della run più recente che ha eseguito il modulo; per ogni parte decide l'esito più recente, e la matrice ripete soltanto le parti mancanti. Un sorgente critico entrato dalla base, che la PR non modifica, non invalida la prova se ogni commit di `develop` che lo tocca viene da una PR con la mutation riuscita, la stessa regola del candidato, che accetta a sua volta le prove per parti. La base incrementale di Stryker è il report più recente della PR su un commit antenato, preferendo la stessa parte, anche dopo cambi di codice; il riferimento di `develop` resta il ripiego senza report, e gli esiti superati per cambi che Stryker non vede li ripete la campagna settimanale. Prima di aggiornare la PR per una base avanzata su soli file neutri per la mutation, il ciclo attende fino a 40 minuti i job della mutation in corso. Estende D317. | Il 2026-11-07 la PR #688 ha visto ripartire più volte la mutation dopo annullamenti e unioni di `develop`, perdendo le parti già concluse; l'owner approva le quattro ottimizzazioni del riuso | Confermato · [Pubblicazione](../docs/operations/RELEASE.md#controlli-proporzionati) |
| D322 | **PR di processo in parallelo** | Cade la regola che limitava a una PR alla volta le modifiche al processo e ai file globali (manifest, lockfile, workflow, classificatore) e che vietava di aprirne altre durante una qualifica. Più PR di processo possono essere aperte e pubblicate insieme: il ciclo mette in fila i merge sotto il blocco e aggiorna e riqualifica la PR la cui base è avanzata su file globali, come per ogni altra PR. Supera D300 per questa parte; restano il worktree per sessione e le autorizzazioni inoltrate. | Richiesta owner del 2026-11-08, durante la pubblicazione della PR #694 con la #693 in qualifica: eliminare la regola in generale | Confermato · [Pubblicazione](../docs/operations/RELEASE.md#contenuto-delle-pr) |
